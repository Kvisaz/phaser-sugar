# Code Review: библиотека утилит для Phaser 3.90

Ниже — обзор найденных проблем и потенциальных улучшений. Фокус на корректности, предсказуемости поведения и совпадении кода с заявленными комментариями.

## Найденные ошибки и риски

### 1) Неверный тип в type guard для спрайта
**Файл:** `src/typeGuards/index.ts`

```ts
export function isSprite(obj: Phaser.GameObjects.GameObject): obj is Phaser.GameObjects.Image {
  return obj.type === "Sprite";
}
```

**Проблема:** функция `isSprite` объявляет, что возвращает `Phaser.GameObjects.Image`, хотя проверяет `obj.type === "Sprite"`. Это приводит к неверной типизации, что может ломать автодополнение, проверку типов и вводить в заблуждение (например, при доступе к API `Sprite`).

**Как исправить:** заменить тип результата на `Phaser.GameObjects.Sprite`.

---

### 2) Сдвиг первого элемента в цепочном layout
**Файл:** `src/layout/arrayLayout/layoutChain.ts`

В цикле `layoutChain` для каждого элемента делается:
1) выравнивание относительно якоря (`alignToAnchor`),
2) выравнивание относительно предыдущего объекта (`alignToNext`).

Для `i = 0` предыдущим объектом становится `anchor`, а если `anchor` — это `firstObject`, первый элемент сначала выравнивается относительно себя, а затем **ещё раз** «отталкивается» от себя методом `alignToNext`. По умолчанию `alignToNext = RIGHT_TO`, что сдвигает первый элемент вправо на его ширину.

**Симптом:** первый элемент в `layoutRow`/`layoutColumn` смещается относительно ожидаемой позиции.

**Как исправить:** применять `alignToNext` только начиная с `i = 1` (или когда `prev !== anchor`), либо изменить логику так, чтобы первый объект только выравнивался относительно anchor.

### 3) Stack.moveAllTo не сохраняет порядок, хотя комментарий говорит обратное
**Файл:** `src/collections/stack/Stack.ts`

```ts
  /** Перекладывает все элементы в другой стек,
   * сохраняя правильный порядок (верх к верху) */
  moveAllTo(target: Stack<T>) {
    for (let i = this.items.length - 1; i >= 0; i--) {
      target.push(this.items[i]);
    }
    this.clear();
  }
```

**Проблема:** при проходе с конца к началу порядок на целевом стеке становится обратным. Это противоречит комментарию «верх к верху». Пример: `[a, b, c]` (c — верх) превращается в `[c, b, a]`, где верх — `a`.

**Как исправить:** переносить элементы с начала к концу, либо использовать временный стек для сохранения порядка.

### 4) Аналогичная проблема в arrayAsStack
**Файл:** `src/collections/stack/arrayAsStack.ts`

```ts
const moveAllFromStackToStackPreserveOrder = <T>(from: Stack<T>, to: Stack<T>) => {
  // вернуть исходный порядок: перекладываем с конца
  for (let i = from.length - 1; i >= 0; i--) to.push(from[i]);
  from.length = 0;
};
```

**Проблема:** фактически порядок меняется на обратный, при этом комментарий вводит в заблуждение.

**Как исправить:** переносить в прямом порядке, либо обновить комментарий, если именно обратный порядок нужен (но тогда название функции тоже стоит изменить).

### 5) safeArray удаляет валидные значения
**Файл:** `src/collections/array/safeArray.ts`

```ts
export const safeArray = <T>(array: (T|undefined)[]): T[] => {
  return array.filter(Boolean) as T[];
};
```

**Проблема:** `filter(Boolean)` удаляет не только `undefined`, но и любые falsy значения (`0`, `""`, `false`). Если библиотека может работать с такими значениями, это приведёт к «тихой» потере данных.

**Как исправить:** фильтровать только `undefined` (или `null`), например `array.filter((v): v is T => v !== undefined)`.

## Возможные улучшения

### 6) ViewPort: масштаб и zoom
**Файл:** `src/components/ViewPort/ViewPort.ts`

В `updateLayout` используется `camera.setZoom(this.scale)`. В Phaser `setScale(x, y)` задаёт `scaleX` и `scaleY`, а `camera.setZoom` принимает одно значение. При несоответствующих `scaleX`/`scaleY` возможна неочевидная связь масштаба `ViewPort` и зума камеры (например, одна ось масштабируется, а zoom — общий).

**Рекомендация:**
- либо использовать `scaleX` (или `scaleY`) явно, если ожидается равномерное масштабирование;
- либо ограничивать `setScale` до одного параметра и документировать это.
